# M6 — Agentic coding performance qualification

## Primary target (owner clarification after report 0007)

**Median >=160 accepted output tokens/s on representative real-world, single-agent coding workloads**, with unchanged target model, Q2_0 weights, precision, correctness, and existing hardware safety limits. A peak, pooled token rate, batched aggregate, copy-only prompt, or all-accepted CPU suffix-lookup case cannot satisfy this target. Preserve the 95–100% productive per-device activity objective and sustained high useful power draw within existing limits; never burn power artificially or optimize a utilization proxy at the expense of throughput or correctness.

Report 0007: warm combined prose median 59.449 feedback tok/s; short code-chat 59.693; favorable repeated copy 157.198. Report 0006 had 161.652 warm median on favorable repeated copy. Neither is evidence of representative agentic throughput. Placement 14/19/15 has 3/82 top-1 disagreements and max KL 0.00805062 against 12/18/18; retain reference and unchanged diagnostic criterion.

## Workload tiers

1. **Controls, non-gating:** existing prose, short code-chat, deliberately repetitive lookup and lookup-disabled counterparts; reproduce old numbers and explain delta, never mix into primary median.
2. **Bounded repository-task replay:** use actual public project code and real historical engineering changes below. Replay normal coding-agent turns with issue/task instruction, relevant source, real read/search/test outputs and previous turn context. This measures decode on realistic coding inputs within current context/token limits, not autonomous tool-use or full-length production performance.
3. **Representative end-to-end agent workflows (primary qualification):** run actual coding tasks covering exploration, edits, tests and follow-up reasoning using existing supported production agent interfaces, tools and repository snapshots. Prefer at least 12 distinct tasks across several real public codebases or authorized, sanitized real agent traces, including unfamiliar files and varied task/context lengths. Freeze the corpus before optimization, keep a held-out set, and report all attempted tasks. Do not download assets or access new repositories without approval; if the available fork or current serving/context capability is insufficient, mark primary gate UNVERIFIED. A measured bounded replay median >=160 does not by itself qualify the primary gate.

## Measurement contract

- Fixed authorized model, template, sampling/seed, engine flags, plan, PCI mapping, context and completion budgets; serialize requests (one logical coding agent, no concurrency or aggregate across agents). Match reference and candidate inputs. Use original 12/18/18 resident plan first, compare lookup off/on and the best qualified combined flags. Separate trace/profiler runs from timing.
- Freeze task set, prompts, task weights and order/scheduling seed before testing; use at least five warm repetitions per replay turn where practical, balanced mode order, one disclosed warm-up per mode. Separate independent repeated trials from within-task turns; do not overweight long or repeated easy tasks.
- For each request report committed returned output tokens, post-first-token accepted output rate (tokens after first / corresponding decode elapsed wall time), native feedback rows/rate, prompt tokens, TTFT, total elapsed, finish reason, accepted/rejected drafts, target verification windows, resets/fallbacks and coverage. Count accepted user-visible tokens only once, not proposed, rejected, replayed or prefill tokens. Do not infer visible streaming speed from buffered HTTP; if token timestamps are unavailable label native timing proxy and do not claim a measured streaming rate. Keep EOS, zero/short outputs and failures visible; undefined rates are null, not zero; a failed/truncated/unscorable task cannot pass the quality/completeness gate.
- Aggregate equal-weighted medians: median across warm repetitions for each fixed turn, median across measured turns for each task, then median across distinct tasks. Report P10/P50/P90, per-task counts/medians, pooled accepted-token rate separately and end-to-end agent completion time including prefill/tools. Require all declared tasks accounted for, sufficient natural output length and valid timing for all primary task scores; no post-hoc exclusions. Existing 2048 total context and 128-output measurements are baseline bounds, not proof of realistic long-context/long-output qualification. Fit safe bounded turns without changing limits; record unsupported longer cases and leave primary gate UNVERIFIED.
- Quality gate: same target model and accepted-token verification, unchanged finite/commit guards, no fallback/prompt leakage; for exact matched greedy controls compare IDs/finish reason; for actual coding tasks run existing scoped tests/checks on isolated authorized fixtures or evaluate patch/diagnosis against predeclared criteria. Report quality and completion rates, not just speed. Optimization cannot reduce quality/completion versus the reference or hide failures.
- Measure passive 250-ms phase-aligned per-GPU utilization, watts, temperatures and existing limits, aligned aggregate watts, valid counts and >=10/90/95% all-device samples using existing tools. Record clocks read-only when available. Report meaningful timing gaps and trace their cause; sampled busy is not proof of occupancy or simultaneous productive work. No clocks, power caps, precision, arena/reserve or context-budget changes.

A 160 tok/s primary pass requires representative workloads, quality and coverage as above, not merely a favorable repetitive fixture. Until that is measured, the status is target not demonstrated.
