## M7 three-device native split-overlap (handoff 0014)

- `--group-native-hip --hip-split-overlap` is an explicit live-smoke qualification mode. With serial prefill, it allocates a runtime-local coherent mapped ready word and payload, attaches per-device aliases through vanilla `Verifier::set_handoff_flags` before init, and relies on native `set_next`, prelaunch, publish, bounded wait and commit. The HIP pair remains in one process. The CUDA/HIP edge is unchanged/serial. This is not full three-device overlap; do not enable by default or use with failing native bulk prefill yet. For diagnostics only, `STRATA_VERIFY_TRACE=1 STRATA_HETERO_OVERLAP_TRACE=1` dumps the native trace ring and completed local ready word after each window.
- New explicit `strata_heterogeneous_overlap_probe` target in each existing native build (not built by default). Build with `cmake --build BUILD_DIR --target strata_heterogeneous_overlap_probe -j28`. Use `python tools/heterogeneous_overlap_probe.py --cuda-worker ABS_CUDA_PROBE --hip-worker ABS_HIP_PROBE --cuda-device 0 --hip-devices 0 1 --rounds 8` with validated runtime-local ordinals and the approved existing environment. A shared 64 KiB memfd is mapped independently, registered by each native runtime, and resolved to each owning device's alias (no foreign pointer/event). The consumer queues production `wait_handoff` (2 s bounded) and `copy_from_mapped`, reports pending, then the producer queues native `handoff_publish`. Readback must match the unique sequence pattern before producer drain/ACK and slot reuse. Tests CUDA→both HIP ranks, reverse directions and HIP0→HIP1 sequentially. This tests GPU publication ordering, not capture/graph or end-to-end inference, and not DMA throughput. No forced GPU kills on failure; report any pending process instead.
