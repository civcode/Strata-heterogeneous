## Source-established scheduling limits

- `experimental/heterogeneous/src/final_pipeline.cpp` (`FinalPipelineSession::execute_discard`, lines 275–330 at f6798aa): one pending window, serial stage loop sends metadata/activation and blocks for the reply before dispatching the next stage. Shared memory avoids some socket payload movement but does not create overlapping stage execution; one reusable activation slot, validation and fences remain. `commit` waits for all valid ACKs even with fanout control.
- `experimental/heterogeneous/src/live_smoke.cpp` (lines 608–618 and 643–681): prefill issues one <=8-row verifier window at a time, commits and checkpoints before submitting next chunk. It is not the vanilla bulk-prefill path. Ordinary greedy decode submits a one-row window using the last committed prediction; there is a true autoregressive dependency. CPU suffix lookup sometimes supplies verified multirow work but is insufficient on current coding replay.
- `cuda_verifier.cpp` and `hip_verifier.cpp`: upload into pinned staging, enqueue/wait execute, download and wait, host copy, commit/wait. `hip_final_verifier.cpp`: upload/fence, final verifier including sampling and finite checks/fence, optional full-logit readback (off in compact mode), separate commit. Inspect native verifier internals and exact timing rather than treating host enqueue spans as device execution. Full resident routed experts/zero callbacks do not prove absence of all CPU/file-backed PLE, embedding or other work.

Sum of the separate A02 roundtrip medians is 16.178 ms; commit barrier median 0.699 ms; illustrative sum 16.877 ms (~59.25 windows/s if one accepted token per window). Approximately 16.89 ms/token corresponds to the observed replay median. Individual roundtrip shares of illustrative serial cycle are ~16%/35%/45%, qualitatively consistent with busy sensors. The scopes are from a different traced run; this is not a joined per-window time accounting or measured GPU duty cycle. The worker spans sum to 14.142 ms, but subtracting independent medians does not measure transfer overhead. A real timestamp join and GPU activity trace are needed. Do not blame OCuLink, PCIe, insufficient expert residency or kernel occupancy without evidence.

160 tok/s requires 6.25 ms per accepted token; operator-reported 120 corresponds to 8.33 ms/token. Eliminating the 0.699 ms commit span alone is insufficient; even the current final inclusive execute span is longer than 6.25 ms. These are not hardware lower bounds. Safe overlap and fewer target passes per accepted output, or substantially faster native compute, are required. Simple layer repartitioning/copy tuning cannot be presumed to close a 2.7x gap.
