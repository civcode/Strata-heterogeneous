# 0032 — real workloads, experimental qualification

Objective: useful tasks and reliable runtime at sustained performance, not tuning to a six-token numerical sample. Prior reports 0027.15 and 0030 remain FAIL under their unchanged diagnostic rules. Functional/task qualification is a new evidence track, not a reclassification or threshold change. Start with vanilla default HC weight/activation settings. Preserve process isolation, layer split, native kernels, stage-owned state, exact transport, finite checks and ACK-before-publication. No reverse grouped or bulk+MTP admission. Explicit opt-in only.

## Vanilla reference

The operator reports vanilla Strata on two R9700 GPUs reaching ~4,000 prefill tok/s and ~120 decode tok/s. See [VANILLA_STRATA_BASELINE.md](VANILLA_STRATA_BASELINE.md) for provenance and limitations. Use these as reference observations, not matched acceptance measurements; compare against the same workload and configuration before claiming a speed ratio or regression.

## Existing path and implementation candidate

Use the existing CLI, resident coordinator and serve.server (no new HTTP server). One greedy active request, full independent reset and model's actual tokenizer/chat template. Stream committed tokens with --stream-tokens; bulk prefill via --native-prefill-chunk; serial baseline via chunk 1. Verified suffix lookup remains buffered only; bounded MTP harness stays separate, no general MTP integration yet.

--workload-mode extends the *requested* grouped resident cap to 32768 context and 4096 new tokens, requiring actual configured cells >= requested, preserves prior default max 8192/256. Native prefill spec/done may now carry up to 32768 token IDs; ordinary verifier windows, 16 MiB payload, native chunk <=2048, existing admission/finite checks unchanged. Rebuild coordinator and both workers; old binary may reject larger specs. Commands beyond 8192 context cap at 384 KiB, CLI text cap 256 KiB opt-in. Not a promise of memory fit or hardware success. Bulk cancellation is cooperative at its completed prefix checkpoint, not per native chunk. Serving remains loopback and single-active greedy; no arbitrary sampling, concurrent batches, general MTP, remote exposure, or unsupported features. Tool rendering/parser already exists in Service; actual tool calling is to be qualified; no model-generated tools executed by benchmark.

## Gates

1. CPU builds/tests and source binding; old defaults reproduce.
2. Actual serial and native bulk on 2K with natural EOS/length and ordinary reset; exact same-mode repeatability, physical links, finite full state, no fallback.
3. API controls incl cancel, next request, clean shutdown. Existing numerical failure remains diagnostic, native workload candidate explicitly experimental.
4. Context tiers 2K/8K/16K/32K: derive new configs changing only max_cells after resource audit; no repack, spill, reserve reduction or force OOM. Preflight, start with serial and bounded lengths then native bulk, step up; exact actual token counts, short and near-cap requests. Stop safely on refusal. Record per-tier memory and context lengths; longer than 32K intentionally not enabled.
5. Performance: at least 3 warm repeats per fixed task/mode, alternate mode order across independent server launches; startup separate. Use existing native timing + phase-aligned passive telemetry, report TTFT, prompt/read throughput, decode accepted throughput, full e2e, natural EOS/length, GPU utilization and memory with actual valid samples. No inferred peak from startup snapshot. Compare baseline before opt-in precision/performance candidates. Do not optimize until evidence.
6. Quality: existing statistical tool for teacher-forced captures, representative tasks with actual tests/rubrics (coding, math, reasoning, document, tools). Distinguish manual unscored, truncated, failed and unsupported. No loosening of mandatory transport/state/runtime integrity or forced sampling. No production admission until review.

MTP general resident serving, per-chunk cancellation and arbitrary sampling are remaining native integration work; no bulk+MTP. No production qualification or performance claim from implementation/CPU evidence.
