At position 2 the predicted token is 96220 in all arms: exceeding KL is independently a failure. All rows' vanilla argmax matched the independently emitted reference token. As a targeted check, forcing the HC weights to BF16 on both vanilla and HIP F16 still exceeded the gate at position 2 (KL 0.002236902), so the default HC Q8 choice alone does not explain the failure. This is a bounded path-isolation result, not proof of a kernel bug: remaining possibilities include numerical differences in the vanilla server's fresh-prefix path vs worker execution, split/commit state, native kernels, and other flags. The two execution paths need state/layer localization before a fix is justified. The 0041 coding answer `30` rather than `14` remains shared and is not a Q8-specific failure.

Three additional naturally stopping INT8 controls, all with identical prompt IDs, matched vanilla/HIP/mixed output IDs `[46110]`, `[38867]`, `[16,20]`. Together with 0041's five controls this is useful but insufficient to override the failed full-logit gate.
