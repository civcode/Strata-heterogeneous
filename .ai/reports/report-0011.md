## Native bulk-prefill correctness — FAIL, do not enable as qualified

Grouped native prefill processed the first `n-1` prompt tokens and then the final token through the ordinary verifier. A03 (430-token chat prompt) and A02 (760-token chat prompt) each ran six independent requests per mode, including five warm repetitions; mode order was serial control then chunk-32 native, not balanced. Every completion was length-capped at 128, and all **12/12** native outputs differed from corresponding grouped serial outputs. A03 first difference was output index 6; A02 differed at the **first output token** (serial 8160, native 760), reproducibly in all six repetitions. This fails exact top-1 comparison; it does **not** by itself identify the numerical or state cause, and no KL/logit threshold has been evaluated or relaxed. Chunk-1 native also reproduced the A03 divergence from serial, so it is not confined to chunk 32.

Additional raw non-chat prompts of 1, 5, 14 and 748 tokens produced matching 2-token or natural-stop outcomes across grouped serial, native chunk 1 and native chunk 32. This limited agreement does not cancel the coding-prompt failure. Native prompt frames validate R-only geometry/size, frame checksum and finite payload in source; physical boundary byte capture and teacher-forced logit/KL comparisons across the grouped HIP domain remain **UNVERIFIED**. No claim of full session-state equivalence.

**PASS, bounded lifecycle:** one real native chunk-32 request was cancelled at the drained 429-token prefix; request 2 reset and completed with the same native output as the independent native control, and all workers cleaned up (`cancel.log`).
